CMPUT 350 Project 1b - Galaga Prototype

Overview
This project builds on the Part 1a engine with transformed drawing contexts,
Bezier paths, shape-based collision checks, registered keyboard notifications,
and a Galaga-style player/enemy prototype.

Implemented
- The engine updates, collides, and renders game objects each frame. Bounding
  rectangles are checked before component shapes, and object pairs are visited
  once per collision pass.
- Collision shapes are defined in local coordinates. The engine supports lines,
  circles, and rectangles; it returns line contact points in local coordinates,
  including for rotated objects. Rectangle/rectangle collision uses a
  separating-axis test so fully contained rectangles are detected.
- Bezier paths support multiple cubic segments. Enemy movement uses sampled arc
  lengths to approximate constant-speed travel.
- The player registers for movement and shooting notifications. Galaga owns the
  key bindings, and player movement is clamped to the playfield.
- Bullets use swept line shapes for collision detection, remember their weak
  parent, select the lowest-y impact point when several contacts are reported,
  and render a collision marker when destroyed.
- Three enemy variants have distinct visuals, attack paths, health, and point
  values. Five waves of eight enemies enter along Bezier paths. Gameplay waits
  until all living enemies have reached formation before launching attacks.
- Enemy attacks are selected deterministically in groups. Enemies fire at the
  player, return to formation after an attack, and award more points when
  destroyed outside formation.
- Galaga tracks score, lives, levels, coins, and game state. It waits for the
  field to be safe before respawning, and clears remaining playfield objects
  when returning to the title screen.

Game State Flow
The title screen waits for coin input (5) and a start input (1). Startup displays
the level and spawns the player. Waves launches five groups of eight ships and
does not transition to gameplay until the entire formation has arrived.
Gameplay schedules deterministic enemy attack groups, tracks kills and score,
and waits for attacking enemies to return before respawning a lost player.
After the final life is lost, Game Over is shown for several seconds; the game
then cleans up the playfield and returns to the title screen.

Extra Credit
- Keyboard setup: press F1 on the title screen, select Move Left, Move Right,
  or Fire with 1-3, then press a key to assign it. Escape cancels an assignment
  or exits the setup screen. Key changes are routed through notifications, so
  the Player implementation does not depend on a particular key.
- Replay: the notification manager records notifications with frame offsets.
  While idle at the title screen, the game automatically replays recorded player
  input as an attract-mode demo. Playback replays inputs and lets normal game
  simulation regenerate outcomes, avoiding duplicate score/death notifications.
  Inserting a coin interrupts the demo.
- Ship capture: some deterministic attack groups send an armored enemy on a
  capture run. The captured ship spins above its captor, can be destroyed by
  friendly fire, and drops back as a double ship if the captor is destroyed.
- Vector2D: Vector2D is an alias for Point2D and is used for values representing
  direction or displacement, including bullet heading and Bezier slope.

Design Notes
- Bullets keep weak parent references, so a shot is removed when its firing
  object dies.
- Enemy path motion uses distance sampling to reduce speed changes from
  unevenly spaced Bezier control points.
- Drawing and collision geometry are local to each object; the engine applies
  the object's position and rotation.
